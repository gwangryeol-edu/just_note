# just_note 화면 구성 / 네비게이션 브리프

디자인 컨셉·비주얼(컬러, 폰트, 톤앤매너)은 별도로 정하며, 이 문서는 화면 구조와 인터랙션 흐름만 정리한 것.

## 전체 레이아웃

흰 배경, 반응형 없음(웹 전용). 화면은 좌/중/우 3분할 고정 레이아웃이며, 페이지 단위 이동이 아니라 한 화면 안에서 표시 상태가 전환되는 구조.

- 왼쪽: 네비게이션 — `list` / `create` / `find` 텍스트 링크, 세로 배치
- 가운데: list 영역 — 기본 상태에서는 note 전체 목록을 원형 배치로 표시
- 오른쪽: detail 영역 — 선택된 note 내용, 또는 create/update 입력폼 표시

## 가운데(list) 영역 — 기본 상태

- 중앙에 "just note" 텍스트
- 그 주위를 감싸는 원형 배치로 작은 박스 10개
- 각 박스에는 해당 note 제목의 첫 글자만 표시
- 박스 배치: 9시 방향이 1번 박스, 그 지점부터 시계 방향으로 2, 3, 4 … 10번까지 이어짐. 1번(9시 방향)이 현재 창에서 가장 최신 note, 시계 방향으로 갈수록 점점 오래된 note
- 10개 박스 자리는 화면에 고정. 카드가 새로 그려지며 쌓이는 무한스크롤이 아니라, 고정된 10칸짜리 창이 전체 note 목록 위를 스크롤에 따라 이동하는 virtualized window 방식
  - 아래로 스크롤 → 오래된 note 방향으로 창 이동
  - 위로 스크롤 → 최신 note 방향으로 창 이동
- 박스 클릭 → 오른쪽 detail에 해당 note 전체 내용 표시

## 오른쪽(detail) 영역 — 기본 상태

- 아무것도 선택하지 않은 기본 상태에서 뭘 보여줄지는 미정 (빈 화면 또는 안내 문구 — 디자인 단계에서 결정)
- 가운데에서 박스를 클릭하면 해당 note의 제목, 작성자, 내용 전체 표시
- find 결과에서 박스를 클릭한 경우엔 update / delete 버튼도 함께 표시

## 네비게이션 동작

- `list` 클릭 → 현재 상태(검색결과, 작성폼 등) 초기화, 가운데는 전체 note 원형 목록으로, 오른쪽 detail은 빈 상태로 복귀
- `create` 클릭 → 오른쪽 detail 자리에 작성자/비밀번호/제목/내용 입력폼 표시
- `find` 클릭 → 가운데 하단에 작성자/비밀번호 입력폼 표시

## create 흐름

- 입력폼: 작성자 / 비밀번호 / 제목 / 내용(마크다운, 작성·미리보기 탭 전환)
- 각 필드 유효성 규칙은 SPEC.md 참고
- 형식 오류 상태에서 submit 누르면 저장 안 되고 오류 필드로 포커스/스크롤 이동
- submit 성공 → 가운데 원형에 새 박스 추가 (박스는 최신 note 자리, 즉 9시 방향에 위치)
- 저장 직후 detail을 어떤 상태로 되돌릴지는 미정 (방금 쓴 note를 그대로 보여줄지, 빈 상태로 돌아갈지)

## find 흐름

- 가운데 하단 입력폼에 작성자 + 비밀번호 입력 후 조회
- 조회 성공(일치하는 note 있음) → 가운데 전체 원형이 검색 결과로 대체됨. 일치하는 note만 원형 배치로 표시되고, 10개 미만이면 그만큼만 표시(나머지 자리는 비움)
- 조회 결과가 없으면 → "일치하는 note가 없습니다. 작성자 혹은 비밀번호를 다시 확인해주세요" 표시
- 검색 결과의 박스 클릭 → detail에 내용 + update / delete 버튼 표시
- update 클릭 → detail 자리에 create와 동일한 폼이 뜨고 기존 내용이 채워진 상태로 시작. 저장 성공 시 find 결과 원형으로 복귀하고 해당 박스 내용 갱신
- delete 클릭 → "『{제목}』 note를 정말 삭제하시겠습니까" 확인창 → 확인 시 원형에서 해당 박스 제거

## 아직 미정 (Figma 작업 중 결정 가능)

- note가 하나도 없을 때 원형을 어떻게 보여줄지 (빈 틀만 둘지, 안내 문구를 넣을지)
- detail 기본(미선택) 상태의 표시 내용
- create 저장 직후 detail 상태
